# ai-glasses-detection — 프로젝트 계획서

> 사진·영상 속 인물이 **AI 안경(카메라 탑재 스마트 안경)** 을 착용했는지 식별하는 비전 모델 구축 프로젝트

- 문서 버전: v0.1 (2026-11-17)
- 상태: 계획 수립 단계

---

## 1. 개요

### 1.1 배경
Ray-Ban Meta 같은 카메라 탑재 AI 안경이 대중화되면서, 상대가 모르는 사이에 촬영·녹화되는 프라이버시 문제가 생기고 있다. AI 안경은 겉모습이 일반 안경과 거의 같아서 사람이 눈으로 구분하기 어렵다.

### 1.2 목표
| 구분 | 목표 |
|---|---|
| 핵심 목표 | 이미지/영상에서 AI 안경 착용 여부를 실시간으로 식별 |
| 정량 목표 | `smart_glasses` 클래스 F1 ≥ 0.85, 일반 안경 → AI 안경 오탐률 ≤ 5% |
| 속도 목표 | 노트북 CPU 기준 ≥ 15 FPS (경량 모델) |
| 확장 목표 | 브랜드/모델 분류, 온디바이스(모바일·엣지) 배포 |

### 1.3 범위
- **포함:** 데이터셋 구축, 검출·분류 모델 학습, 평가, 웹캠 실시간 데모
- **제외(MVP):** 개인 신원 식별, 영상 녹화 여부 판정, 상용 앱 출시

## 2. 문제 정의

### 2.1 클래스 정의
| ID | 클래스 | 정의 | 포함 예시 |
|---|---|---|---|
| 0 | `no_glasses` | 눈 주변에 안경 없음 | 맨얼굴, 렌즈만 착용 |
| 1 | `regular_glasses` | 카메라 없는 일반 안경 | 뿔테, 금속테, 무테 |
| 2 | `sunglasses` | 카메라 없는 선글라스 | 일반 선글라스 |
| 3 | `smart_glasses` | 카메라/LED가 있는 AI 안경 | Ray-Ban Meta, Oakley Meta 등 |

> 확장 단계에서 `smart_glasses`를 브랜드별 하위 클래스로 나눈다.

### 2.2 판별 단서
- 프레임 앞면 모서리의 **카메라 렌즈 구멍**
- 반대쪽 모서리의 **녹화 표시 LED**
- 일반 안경보다 **두꺼운 다리(템플)** (배터리·스피커 내장)
- 다리 측면의 **터치패드**

### 2.3 핵심 난제
1. **세밀 분류:** 클래스 간 차이가 수 mm 크기의 부품뿐이다.
2. **작은 객체:** 원거리에서는 단서가 몇 픽셀밖에 안 된다.
3. **데이터 부족:** AI 안경 착용 이미지가 공개된 것이 적다.
4. **Hard negative:** 두꺼운 뿔테 안경을 AI 안경으로 잘못 판단하기 쉽다.

## 3. 시스템 아키텍처

### 3.1 2단계 파이프라인 (메인)
```
[입력 이미지/프레임]
        │
        ▼
[Stage 1] 안경 영역 검출 — YOLO (v8n/v11n 등 경량 모델)
        │  bbox (클래스 무관: eyewear)
        ▼
[Crop & Resize] 안경 영역 + 여유 margin 20% → 224×224 또는 384×384
        │
        ▼
[Stage 2] 세밀 분류 — ConvNeXt-T / EfficientNet-B0 / ViT-S
        │
        ▼
[출력] 클래스 + 신뢰도 + bbox 시각화
```

**2단계로 나누는 이유**
- Stage 1은 "안경이 어디 있는가"만 찾으면 되니 쉽다.
- Stage 2는 잘라낸 고해상도 이미지에서 미세한 단서에 집중할 수 있다.
- 두 단계를 따로 개선하고 디버깅할 수 있다.

### 3.2 비교군: 단일 단계 검출기
- YOLO 하나로 4개 클래스를 바로 검출한다.
- 속도와 정확도를 2단계 방식과 비교하는 실험 축으로 쓴다.

### 3.3 (선택) 멀티모달 확장
- 일부 스마트 안경은 BLE 광고 패킷을 내보낼 수 있다. 실제 기기로 신호를 수집해 확인한 뒤, 비전 결과와 결합(late fusion)하는 방안을 검토한다.

## 4. 데이터 계획

### 4.1 수집 출처
| 출처 | 대상 클래스 | 예상 수량 | 비고 |
|---|---|---|---|
| CelebA (Eyeglasses 속성) | 0, 1, 2 | 5,000+ | 연구용 라이선스 확인 |
| MeGlass 등 안경 데이터셋 | 1 | 2,000+ | |
| 제품·리뷰 이미지 | 3 | 500~1,000 | 출처 기록, 연구 목적으로만 사용 |
| **직접 촬영** | 1, 2, 3 | 1,500+ | 핵심 데이터, 동의서 필수 |
| 합성 데이터 | 3 | 2,000+ | 얼굴에 안경 PNG 합성 |

### 4.2 직접 촬영 프로토콜
- **참여자:** 최소 10명 (사람 단위로 분할하려면 다양성 필요)
- **기기:** AI 안경 1~2종, 일반 안경 3종 이상 (뿔테 필수), 선글라스 1종
- **변수 조합:**
  - 거리: 0.5m / 1m / 2m / 3m / 5m
  - 각도: 정면 / ±30° / ±60° / 측면
  - 조명: 실내 형광등 / 자연광 / 역광 / 저조도
  - 배경: 강의실, 복도, 야외
- **방식:** 짧은 영상 촬영 후 프레임 추출 (1~2 fps). 비슷한 프레임은 중복 제거한다.

### 4.3 합성 데이터 파이프라인
1. AI 안경 제품 이미지에서 배경을 제거해 투명 PNG를 만든다 (rembg 등).
2. 얼굴 랜드마크를 검출한다 (MediaPipe Face Mesh).
3. 눈 위치에 맞춰 안경 PNG를 회전·스케일·원근 변환해 합성한다.
4. 색감 보정과 그림자 추가로 이질감을 줄인다.
5. 합성 데이터는 **학습에만** 쓰고, 평가는 실제 촬영 데이터로만 한다.

### 4.4 라벨링 가이드
- **도구:** CVAT 또는 Roboflow
- **bbox 기준:** 안경 프레임 전체 (다리 일부 포함), 눈썹은 제외
- **애매한 경우:**
  - 측면이라 카메라가 안 보이면 → 실제 착용 기기 기준으로 라벨링 (촬영 기록 참고)
  - 판별 불가 → `ignore` 태그
- **품질 관리:** 전체의 10%를 2명이 교차 검수한다 (일치율 ≥ 95% 목표).

### 4.5 데이터 분할
- **사람(Subject) 단위로 분할한다.** 같은 사람이 train/val/test에 동시에 들어가면 안 된다.
- 비율: train 70% / val 15% / test 15%
- test셋에는 hard negative(두꺼운 뿔테)를 의도적으로 포함한다.

### 4.6 클래스 불균형 대응
- 가중치 샘플링 (WeightedRandomSampler)
- Focal Loss
- `smart_glasses` 집중 증강

## 5. 모델 계획

### 5.1 Stage 1 — 안경 검출기
| 항목 | 설정 |
|---|---|
| 모델 | YOLOv8n / YOLO11n (Ultralytics) |
| 입력 | 640×640 |
| 클래스 | `eyewear` 1개 (선택: 얼굴 함께 검출) |
| 사전학습 | COCO 가중치 |
| 지표 | mAP@0.5 ≥ 0.90 |

### 5.2 Stage 2 — 세밀 분류기
| 후보 | 장점 | 단점 |
|---|---|---|
| EfficientNet-B0 | 가볍고 빠름 | 미세 특징 포착 한계 |
| ConvNeXt-Tiny | 정확도와 속도 균형 | 중간 크기 |
| ViT-S/16 (DINOv2) | 사전학습 특징이 강력함 | 데이터가 적으면 불안정 |

- **입력 해상도:** 224 → 384 비교 실험 (해상도가 핵심 변수)
- **학습 전략:** 사전학습 백본 고정 → head 학습 → 전체 미세조정

### 5.3 증강 (Albumentations)
- 기하: 회전 ±15°, 스케일 0.8~1.2, 원근 변환
- 색상: 밝기·대비, HSV, 블러, 노이즈, JPEG 압축
- 주의: **좌우 반전은 허용**한다. 단, 카메라와 LED의 좌우 위치가 바뀌므로 기기별 특성을 학습해야 하는 확장 단계에서는 재검토한다.
- Random Erasing은 단서 영역을 지울 수 있으므로 약하게 적용한다.

### 5.4 학습 설정 (초기값)
| 항목 | 값 |
|---|---|
| Optimizer | AdamW |
| LR | 1e-4 (백본) / 1e-3 (head), cosine decay |
| Batch | 32 |
| Epoch | 30~50, Early stopping (patience 7) |
| Loss | CrossEntropy → Focal Loss 비교 |
| 환경 | Colab Pro / 연구실 GPU |
| 실험 관리 | Weights & Biases |

### 5.5 실험 계획
| 실험 ID | 내용 | 비교 대상 |
|---|---|---|
| E1 | 단일 YOLO 4-class | 베이스라인 |
| E2 | 2단계 (YOLO + EfficientNet-B0, 224) | E1 |
| E3 | Stage 2 백본 교체 (ConvNeXt, ViT) | E2 |
| E4 | 크롭 해상도 224 vs 384 | E3 최고 모델 |
| E5 | 합성 데이터 유무 | E4 |
| E6 | Focal Loss vs CE | E4 |
| E7 | INT8 양자화 전후 | 최종 모델 |

## 6. 평가 계획

### 6.1 지표
| 범주 | 지표 |
|---|---|
| 검출 | mAP@0.5, mAP@0.5:0.95 |
| 분류 | Accuracy, 클래스별 Precision/Recall/F1, Macro-F1 |
| 핵심 | **`regular_glasses` → `smart_glasses` 오탐률** |
| 속도 | FPS, 프레임당 지연시간(ms), 모델 크기(MB) |

### 6.2 강건성 평가 (조건별 분리 측정)
- 거리별 정확도 곡선 (0.5m ~ 5m)
- 각도별 정확도 (정면 ~ 측면)
- 조명별 정확도
- 학습에 없던 안경 모델에 대한 일반화

### 6.3 오류 분석
- 혼동행렬
- 오분류 이미지 갤러리 정리
- Grad-CAM으로 모델이 카메라/LED 영역을 실제로 보는지 확인

## 7. 배포 및 데모

### 7.1 경량화
- PyTorch → ONNX → (선택) TFLite / CoreML
- INT8 양자화 (정확도 손실 ≤ 2%p 목표)

### 7.2 데모 앱
- **Streamlit 또는 Gradio** 웹앱
  - 이미지 업로드 → 결과 표시
  - 웹캠 실시간 모드 (bbox + 클래스 + 신뢰도 오버레이)
- 프레임 간 결과 스무딩: 최근 N 프레임 다수결로 깜빡임을 줄인다.

## 13. 윤리 및 개인정보

- 모델은 **기기만 식별하고 사람의 신원은 식별하지 않는다.**
- 직접 촬영 참여자 전원에게 **서면 동의**를 받는다 (사용 목적, 보관 기간, 폐기 방법 명시).
- 공개 리포지토리에는 원본 얼굴 이미지를 올리지 않는다. 예시 이미지는 블러 처리한다.
- 웹 수집 이미지는 출처를 기록하고 연구 목적으로만 사용한다.
- 데모 앱은 입력 영상을 저장하지 않는다.
